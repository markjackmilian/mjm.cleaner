## Differenze rispetto al C#

| Punto | C# | Swift | Tipo |
|---|---|---|---|
| Messaggio d'errore | `Exception.Message` di .NET | `strerror(errno)` | accettata (spec §5.3) |
| Lettura dei collegamenti | `FileInfo`/`DirectoryInfo` (lstat, misurato) | `itemInfo` con `lstat` | identica |
| Semantica delle stringhe di percorso | unità UTF-16, `OrdinalIgnoreCase` | byte UTF-8 per separatori e punti; ripiegamento per scalare a lunghezza invariata; test solo-Swift in PathGuardTests/PathTextTests/SimpleGlobTests | equivalente a OrdinalIgnoreCase di .NET 10 (confronto esaustivo sugli scalari nella review del Task 4; ı, ſ e U+16EA0–U+16EDF esclusi) |
| Cartella dati | ~/Library/Application Support/mjm.cleaner | …/<bundle id> | voluta (spec §4.4) |
| Commento sull'età dei collegamenti in ClearContents | diceva «timestamp del bersaglio» | corretto: lstat del collegamento, come .NET misurato | solo commento |
| Misura reale di una cartella prima di cancellarla | `EnumerateFiles(…, AllDirectories)` scende nei collegamenti a cartelle | non scende nei collegamenti (spec originale §7); un elemento-cartella che è un collegamento accredita 0 | voluta |
| Root dichiarata nulla | ramo dedicato «root dichiarata mancante» | impossibile per tipo; la root vuota è negata da validateRoot | per costruzione |
| Chiave dei verdetti delle root in CleanEngine | Dictionary OrdinalIgnoreCase | byte UTF-8 del percorso ripiegato (OrdinalIgnoreCase); test solo-Swift | equivalente (correzione della review del Task 9) |
| Deduplicazione in ConfirmationRows | StringComparer.Ordinal | equivalenza canonica di String: NFC/NFD dello stesso file in una sola riga | voluta (evita il doppio conteggio) |
| Formato di StartedAtUtc | "O" di .NET (7 decimali) | ISO 8601 con millisecondi | accettata: dati nuovi (spec §2) |
| Diario pending-*.jsonl | assente (catch-all in CleanEngine) | presente | voluta (spec §8.2) |

| ENOTDIR (genitore diventato un file, solo in race) | `DirectoryNotFoundException` / sentinella 1601 | classificato «in uso»; `accept` respinge l'elemento | accettata (lato sicuro: propone meno) |
| Decodifica di `settings.json` | un campo intero `null`, `12.0` o un valore oltre Int32 rendono il file illeggibile (tutti i default); `"ProjectRoots": null` è accettato (la proprietà diventa null, gli altri campi restano) e `[null]` è accettato (l'elenco conserva un elemento null) | `null` → default del solo campo (anche `ProjectRoots` → `[]`); `12.0` e valori a 64 bit accettati; `[null]` → tutti i default | mista: più tollerante su campi null e numeri, più severa su elementi null |
| Escape delle righe dei log (`jsonLine`) | `JsonSerializer`: non-ASCII e `<>&'` come `\uXXXX` | non-ASCII grezzo in UTF-8; U+2028, U+2029 e U+0085 non escapati | equivalente (stesso valore decodificato) |
| Segnali del processo figlio | `pal_process.c` azzera i gestori personalizzati e conserva i `SIG_IGN` ereditati | maschera vuota e disposizioni predefinite per tutti i segnali, anche i `SIG_IGN` ereditati | accettata |
| `SimpleGlob` senza maiuscole | `MatchesSimpleExpression` usa `ToUpperInvariant` per unità UTF-16: «ı» resta invariata (`MatchesSimpleExpression("I", "ı", true)` è falso) e «ſ» diventa «S» | stesso ripiegamento `OrdinalIgnoreCase` di `PathText` (ı e ſ invariati) | accettata: diverge solo «ſ» (lato sicuro per include e marcatori); da rivedere se si useranno glob di esclusione non ASCII |
| EACCES/EPERM da `rmdir` | `IOException` → «in uso»; `DoneStepViewModel.LooksLikePermissionError` riconosceva il testo inglese del messaggio .NET | `.accessDenied` direttamente | voluta; il piano 4 porta `LooksLikePermissionError` come `kind == .accessDenied`, non sul testo |
| Implementazione di `LocalFileSystem` (spec §5.2) | — | la spec citava `realpath` e `removefile`; si usano `readlink` + normalizzazione testuale (come `ResolveLinkTarget`) e una `removeTree` propria (come `Directory.Delete`, attraversa anche i punti di montaggio) | voluta (parità con .NET) |

| Testo di Docker e dei progetti | metodi .NET su unità UTF-16 (`Split`, `Trim`, `Contains`/`StartsWith`/`EndsWith` `Ordinal` e `OrdinalIgnoreCase`, `Distinct`, `Order`, `ToLowerInvariant`) | `DockerText` su scalari e byte UTF-8, con il ripiegamento di `PathText`; test solo-Swift in DockerTextTests | equivalente (White_Space e `ToLowerInvariant` confrontati su tutti gli scalari) |

## Candidati a miglioramento (notati, non applicati)

Spec §12: si annotano qui e non si cambiano durante il porting.

| Punto | Comportamento attuale (replicato) | Proposta |
|---|---|---|
| Collegamento a cartella dentro una cache (clearContents) | `File.Exists` lo vede come assente: l'elemento fallisce come «non trovato» e il collegamento resta | eliminare il collegamento con `deleteFile` quando `itemInfo` dice `.symbolicLink` |
| Byte accreditati per un collegamento a file | la dimensione del collegamento stesso (lunghezza del percorso di destinazione) | accreditare 0: eliminare il collegamento non libera lo spazio del bersaglio |
| errno residui (EROFS, ENOSPC, EIO…) | classificati «in uso», come ogni IOException .NET | categoria dedicata o «altro» |
| APFS ripiega più di OrdinalIgnoreCase (U+212A→k, ſ→s) | un elemento manipolato "~/Des\u{212A}top/x" con la stessa root supera la deny-list testuale e APFS lo risolve in ~/Desktop (uguale nel C#) | confrontare la deny-list sul percorso risolto dal filesystem (realpath/F_GETPATH) oltre che sul testo |
| Finestra fra `lstat` e `opendir` in `deleteDirectoryRecursively` | una cartella sostituita da un collegamento in quella finestra verrebbe seguita (stessa finestra di .NET) | attraversamento con `openat`/`unlinkat` e `O_NOFOLLOW`, in forma iterativa |
| Lettura dei file di progetto in `ProjectReferenceScanner` | legge con `readData`, che segue i collegamenti, mentre il tetto di 1 MiB usa la dimensione `lstat` del collegamento stesso: un file collegato aggira il tetto, e una FIFO col nome di un file di progetto bloccherebbe `open()` senza possibilità di annullamento, così `analyze` non tornerebbe mai (stesso comportamento del C#) | aprire con `O_NOFOLLOW` o controllare che sia un file regolare prima di leggere |
